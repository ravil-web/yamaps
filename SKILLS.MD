# Скиллы агента (token-saving toolkit)

> Принцип: всё, что можно посчитать кодом — считай кодом. В LLM подавай только сжатые результаты, а не сырьё. Сырой код/HTML/JSON НЕ цитируется в чат целиком — только пути, диапазоны строк и краткие сводки.

---

## S0. Бюджет контекста (правило поверх всех скиллов)
- Никогда не вставляй в контекст файл целиком, если нужен фрагмент. Используй `grep`/диапазоны строк.
- Любой сырой вывод > 50 строк → сначала прогнать через скилл-суммаризатор, в чат пускать только сводку.
- Промежуточные артефакты хранить в файлах (`docs/`, `.cache/`), а не в истории диалога. В следующих шагах ссылаться путём, а не пересказом.

---

## S1. `code_map` — карта кода без чтения кода
Назначение: получить структуру исходника без подачи кода в LLM.
Реализация (скрипт, без LLM):
```bash
# дерево + размеры
find legacy -type f -name "*.py" -printf "%p %s байт\n"
# сигнатуры функций/классов
grep -rnE "^\s*(def|class|async def) " legacy --include=*.py
# импорты
grep -rhE "^\s*(import|from) " legacy --include=*.py | sort -u
# CLI/конфиг/константы (кандидаты в параметры парсинга)
grep -rnE "argparse|click|os.environ|getenv|TIMEOUT|DELAY|RETRY|PROXY|USER_AGENT|LIMIT|=[[:space:]]*[0-9]" legacy --include=*.py
```
Выход: `docs/code_map.txt`. В LLM подаётся только этот файл, а не исходники.
**Экономия:** заменяет «прочитать весь проект» сотнями токенов вместо десятков тысяч.

---

## S2. `params_extract` — авто-сбор параметров парсинга
Назначение: собрать параметры без ручного чтения кода моделью.
Шаги (скрипт + минимальный LLM-проход только по сводке S1):
1. Скриптом собрать все `argparse`-аргументы, env-переменные, числовые константы → черновик `docs/parser_params.draft.json`.
2. LLM получает ТОЛЬКО черновик (не код) и приводит к схеме: `{name, type, default, group, ui_widget, description}`.
Выход: `docs/parser_params.md` + `params_schema.json` (используется фронтом).
**Экономия:** LLM работает с компактным JSON, а не с кодом.

---

## S3. `dead_code_scan` — поиск мёртвого кода скриптом
Назначение: список DROP-кандидатов без анализа кода моделью.
```bash
pip install vulture
vulture legacy --min-confidence 80 > docs/dead_code.txt
# неиспользуемые импорты / переменные
ruff check legacy --select F401,F841 > docs/unused.txt
```
LLM лишь утверждает финальный список по этим отчётам (короткий ввод).
**Экономия:** анализ достижимости делает инструмент, не модель.

---

## S4. `summarize_blob` — суммаризатор больших выводов
Назначение: сжать любой большой текст (логи, HTML, JSON-ответы, stacktrace) перед подачей в LLM.
Правило: входной блоб → сначала детерминированно урезать (head/tail, grep по ключевым строкам), и только остаток (≤ N строк) при необходимости передавать модели.
```bash
# пример: из лога парсинга только ошибки и итоги
grep -nE "ERROR|Traceback|captcha|BLOCKED|saved|total" run.log | tail -n 40
```
**Экономия:** мегабайтные логи/HTML не попадают в контекст.

---

## S5. `fixture_test` — тесты на фикстурах, а не на «живом» парсинге
Назначение: не гонять реальные сетевые запросы и большие HTML через LLM при отладке извлечения.
Шаги:
1. Один раз сохранить сырые ответы Яндекса в `tests/fixtures/*.html|*.json` (скриптом).
2. Тесты извлечения гоняются офлайн по фикстурам.
3. LLM при падении теста получает только diff `expected vs actual` (через S4), не весь HTML.
**Экономия:** отладка парсинга без повторных сетевых вызовов и без подачи HTML в чат.

---

## S6. `diff_review` — ревью по диффу, а не по файлам
Назначение: проверять работу субагентов по `git diff`, а не перечитывая файлы.
```bash
git --no-pager diff --stat        # сначала охват изменений
git --no-pager diff -- <file>     # детально только подозрительные файлы
```
Правило: оркестратор ревьюит ТОЛЬКО diff. Логика парсинга в CORE: убедиться, что diff в `parser_core/` не трогает селекторы/задержки (grep по diff).
**Экономия:** не перечитываются неизменённые файлы.

---

## S7. `subagent_brief` — упаковка задач субагенту без лишнего контекста
Назначение: давать дешёвому субагенту минимально достаточный контекст.
Шаблон передачи:
- вместо файла целиком — путь + нужные диапазоны строк (`file.py:120-180`);
- вместо «всего проекта» — `docs/code_map.txt` + `docs/api.md`;
- запрет на возврат сырья: субагент возвращает только патч/файл и краткий чек-лист приёмки.
**Экономия:** короткий вход и выход на каждой делегированной задаче.

---

## S8. `lint_autofix` — автоформат без LLM
Назначение: стиль/формат не править моделью.
```bash
ruff check --fix . && ruff format .   # python
npx prettier --write .                # frontend
```
Запускается как рутинный шаг, результат в чат не выводится (только «OK / N исправлений»).
**Экономия:** ноль токенов на форматирование.

---

## S9. `progress_state` — внешняя память вместо длинного диалога
Назначение: не таскать историю в контексте.
Файл `PROGRESS.md` (машиночитаемая шапка):
```yaml
stage: 4            # текущий этап
done: [0,1,2,3]
core_frozen: true   # логика парсинга перенесена и проверена
params_file: docs/parser_params.md
api_contract: docs/api.md
open_bugs: []
```
Правило: при возобновлении работы читать только `PROGRESS.md` + указанные в нём файлы, а не пересказ предыдущих шагов.
**Экономия:** контекст не раздувается историей; рестарт «дешёвый».

---

## S10. `cache_keys` — кэш сетевых ответов
Назначение: исключить повторные запросы к Яндексу при разработке/тестах.
- Кэшировать ответы по ключу `hash(url+params)` в `.cache/`.
- При повторном запуске брать из кэша.
**Экономия:** не оплачивается ни сеть, ни повторная суммаризация одинаковых ответов.

## Общие правила экономии (метаскиллы)
1. **Детерминизм важнее LLM:** есть скрипт/линтер/тест — используй его, не модель.
2. **Сводка вместо сырья:** в контекст только результаты S1/S4, не исходники.
3. **Файлы вместо диалога:** артефакты в `docs/`/`.cache/`, ссылки путём (S9).
4. **Диффы вместо файлов** при ревью (S6).
5. **Дешёвый субагент = короткий бриф** (S7), сложное решение — оркестратор.
6. **Кэшируй сеть** (S10) и **фикстурь тесты** (S5), чтобы не платить за повторы.
