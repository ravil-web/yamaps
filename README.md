# Yandex Maps Parser

Веб-приложение для поиска и выгрузки организаций из Yandex Maps по запросу и области на карте.  
Backend на FastAPI, хранение в SQLite, интерфейс - одностраничный SPA без внешних UI-зависимостей.  
Парсинг опирается на изолированный `parser_core/`, а селекторы и поведение Selenium остаются в `legacy/` как immutable-база.

## Что умеет

- строить задачу парсинга по запросу и области `bbox` или `polygon`;
- показывать прогресс, найденные организации и сообщения статуса;
- останавливать задачу вручную;
- сохранять результаты в SQLite сразу по мере получения;
- экспортировать результаты в `csv`, `xlsx` и `json`;
- работать с Yandex Maps API key и без него;
- запускаться в demo-mode для офлайн-проверки UI и E2E.

## Установка

1. Склонируйте проект и перейдите в каталог `parser_ya_maps_new`.
2. Создайте `.env` на основе `.env.example`.
3. Установите зависимости:

```bash
pip install -r requirements.txt
```

## Конфигурация

Основные переменные окружения:

- `YANDEX_MAPS_API_KEY` - ключ Yandex Maps JavaScript API 2.1;
- `APP_HOST` - адрес запуска, по умолчанию `127.0.0.1`;
- `APP_PORT` - порт запуска, по умолчанию `8000`;
- `OPEN_BROWSER` - `1` открывает браузер при `python run.py`, `0` отключает;
- `APP_DATA_DIR` - каталог для `app.db`, по умолчанию `data`;
- `PARSER_DEMO_MODE` - `1` включает детерминированный offline-режим.

Пример уже есть в [.env.example](./.env.example).

## Запуск локально

Запуск через штатный entrypoint:

```bash
python run.py
```

По умолчанию приложение поднимается на `http://127.0.0.1:8000` и пытается открыть браузер.

Если ключ Yandex отсутствует, приложение всё равно стартует.  
В этом случае карта отключается, а UI показывает подсказку по настройке ключа.

## Запуск в Docker

```bash
docker compose up
```

`docker-compose.yml` пробрасывает порт `8000`, подключает `./data` как volume и читает `.env`, если он есть.

## UI workflow

1. Откройте главную страницу.
2. Укажите поисковый запрос.
3. Выберите область на карте: прямоугольник или полигон.
4. Настройте параметры парсера, если нужно.
5. Запустите задачу.
6. Отслеживайте прогресс, список результатов и маркеры на карте.
7. При необходимости нажмите Stop.
8. Экспортируйте результаты в `csv`, `xlsx` или `json`.

Схема параметров подгружается с `/api/params/schema`, поэтому форма в UI собирается из актуального контракта.

## Demo-mode

`PARSER_DEMO_MODE=1` включает детерминированный offline parser (`app/demo.py`).  
Он нужен для демонстраций, smoke-checks и E2E без обращения к Yandex Maps и без Selenium.

В этом режиме:

- результаты генерируются предсказуемо;
- UI и экспорт можно проверить без внешних зависимостей;
- удобно прогонять тестовые сценарии в среде без ключа.

## API и параметры

API доступно под префиксом `/api`:

- `POST /api/jobs` - создать задачу;
- `GET /api/jobs/{id}` - получить статус;
- `GET /api/jobs/{id}/results` - получить постраничные результаты;
- `POST /api/jobs/{id}/stop` - остановить задачу;
- `GET /api/jobs/{id}/export?format=csv|xlsx|json` - выгрузить данные;
- `GET /api/params/schema` - получить schema параметров;
- `GET /api/config` - получить публичную конфигурацию карты;
- `GET /api/health` - healthcheck.

Поддерживаются две области поиска:

- `bbox` - прямоугольник `west,south,east,north`;
- `polygon` - замкнутый полигон в координатах `[longitude, latitude]`.

Для задачи принимаются только параметры из `params_schema.json`.  
Остальные значения берутся из исходных дефолтов парсера.

Экспорт формируется из всех уже сохранённых результатов, включая частичные данные, если задача была остановлена или завершилась с ошибкой.

## Тесты

```bash
pytest
```

Набор тестов покрывает:

- валидацию области, разбиение на тайлы, нормализацию и дедупликацию;
- API жизненного цикла задач, stop, config, schema и export;
- E2E-сценарии на demo-mode;
- частичный экспорт и поведение при пустом результате или ошибке парсера.

## Архитектура

Коротко по потоку данных:

`Browser SPA -> FastAPI -> JobManager -> ParserCore -> SQLiteStore`

Состав системы:

- backend: Python, FastAPI, Pydantic;
- фоновые задачи: один управляемый background thread на задачу;
- хранение: SQLite через `sqlite3`;
- parser core: `parser_core/` поверх frozen legacy Selenium-логики;
- frontend: dependency-free HTML/CSS/JavaScript SPA;
- карта: Yandex Maps JavaScript API 2.1.

Пояснение по парсингу:

- область переводится в bbox и при необходимости делится на сетку тайлов;
- для каждого тайла строится Yandex Maps search URL;
- legacy-логика сбора URL и разбора карточек вызывается без переписывания селекторов;
- результаты нормализуются, фильтруются по полигону и дедуплицируются.

## Ограничения

- Для реального парсинга нужен установленный Chrome/Chromium и рабочая Selenium-среда.
- DOM Yandex Maps, captcha и антибот-поведение внешне нестабильны, поэтому результаты и поведение могут меняться.
- Stop работает кооперативно: задача останавливается между этапами, но активные ожидания Selenium могут задержать остановку.
- Живую карту и маркеры нельзя полноценно проверить без Yandex Maps API key.
- При отсутствии ключа карта отключается, но сам backend, API, экспорт и demo-mode остаются доступными.

## Статус проекта

Исторический и селекторный baseline сохранён в `legacy/` и не должен изменяться.
